# Пространства и доступ без регистрации

Этот каталог содержит согласованный план перехода Moapp от одного общего PIN и
одного набора расходов к профилям без регистрации, нескольким пространствам,
одноразовым приглашениям, быстрому переключению и восстановлению доступа.

Документы являются планом, а не описанием уже реализованного поведения.

## Граф выполнения

```text
00 Контракт зафиксирован
          |
00a Compatibility-релиз -> production и проверка устройств
          |
01 Схема и миграция
          |
02 Identity / sessions / workspaces
       /     \
03 Tenant    04 Access links
scoping      & recovery
       \     /
05 Client foundation / offline
          |
06 Client UX
          |
07 Integration / rollout / QA
```

`00a` — отдельный production release и gate, а не часть большого cutover. После
завершения `02` задачи `03` и `04` можно выполнять параллельно только при
раздельном владении файлами. Клиентскую подготовку из `05` можно начать раньше
по зафиксированному контракту, но интеграционные проверки требуют готовности
`02`–`04`.

## Границы задач для агентов

| План | Основные файлы | Не должен менять без координации |
|---|---|---|
| 00a | текущие `api.ts`, `App.tsx`, update UI/SW, compatibility tests | schema и новый workspace API |
| 01 | `server/src/db.ts`, migration tests | HTTP API и клиентский UX |
| 02 | `auth.ts`, `types.ts`, новые `users.ts`/`workspaces.ts` | доменные SQL-запросы и recovery |
| 03 | domain route plugins, `expenses.ts`, `categories.ts`, `analytics.ts`, `sync.ts`, `rates.ts` | `app.ts`, auth и токены доступа |
| 04 | самостоятельный access route plugin и access tests | `app.ts`, auth helpers и domain data |
| 05 | `client/src/types.ts`, новые scoped API/offline/state/capability modules, `sw.js`/Vite | `App.tsx`, `main.tsx` и визуальная переработка экранов |
| 06 | `App.tsx`, `main.tsx`, UI, `styles.css`, удаление legacy `api.ts`/`offline.ts` и их tests | серверная схема и миграции |
| 07 | `app.ts`, контракты, README, env/deploy, сквозные тесты | новые продуктовые возможности |

Это одновременно рекомендуемые границы будущих задач агентов: один агент на
одну строку. `03` и `04` запускаются параллельно после `02`; остальные этапы
последовательны. `07` выполняет отдельный integration-owner, а не один из
параллельных авторов `03`/`04`.

`server/src/app.ts`, `server/src/types.ts`, `client/src/types.ts` и API-контракты
являются точками интеграции. Изменения в них должны следовать
[00-architecture.md](./00-architecture.md), а не вводить новый контракт внутри
отдельной задачи.

## Правила реализации

- Активное пространство никогда не определяется только состоянием браузера:
  сервер проверяет membership на каждом запросе.
- Любой SQL-запрос к расходам, категориям или sync содержит `workspace_id`, даже
  если маршрут уже защищён pre-handler'ом.
- Старые unscoped-маршруты не продолжают работать «временно»: после cutover они
  отвечают `410 UPGRADE_REQUIRED` и ничего не меняют.
- Capability-секреты не попадают в URL запроса, логи, localStorage, IndexedDB или
  Cache Storage.
- Нельзя отправлять накопленную offline-операцию в текущее пространство без её
  сохранённого `userId + workspaceId`.
- Миграции 1 и 2 не переписываются. Переход выполняется новой forward-only
  миграцией и репетируется на копии production SQLite.
- Проект автоматически выкладывает `main`. Несовместимые части `01`–`06` нельзя
  отправлять по отдельности в production: координатор объединяет их локально и
  отправляет одним проверенным cutover после полного integration gate.
- Коммиты следуют Conventional Commits.

## Общий Definition of Done

- Два пространства могут иметь одинаковые системные ID категорий и одинаковые
  UUID объектов без пересечения данных.
- Пользователь быстро переключается между ранее добавленными пространствами, а
  новое пространство после создания сразу становится активным.
- Чистый браузер видит кнопку «Создать пространство»; PIN не является обычным
  способом входа.
- Invite создаёт нового участника, device link добавляет устройство к
  существующему профилю, recovery восстанавливает тот же профиль со всеми
  сохранившимися memberships.
- Recovery нельзя ротировать незаметно: интерфейс до подтверждения показывает
  новую ссылку и явно требует сохранить её; старая действует до завершения.
- Удалённый участник больше не может читать или отправлять изменения на сервер.
  Уже скачанную offline-копию невозможно стереть удалённо, и это ограничение
  явно отражено в продукте и документации.
- `npm run typecheck`, `npm test` и `npm run build` проходят.
