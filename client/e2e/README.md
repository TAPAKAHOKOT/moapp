# Проверки в настоящем движке Safari

Скрипты гоняют приложение в Playwright WebKit с профилем iPhone 15 (и в Chromium по флагу `chromium`):
снимают экраны, покадрово записывают свайп карточки и обновления аналитики, сравнивают снимки попиксельно.
Они не входят в `npm test`: браузеры тяжёлые, а сценарии нужны перед выкладкой изменений в раскладке, жестах
и анимациях.

## Подготовка

```bash
npm install                       # playwright, pngjs, pixelmatch — в devDependencies корня
npx playwright install webkit     # один раз; chromium — по желанию
```

Нужны запущенные dev-серверы (`npm run dev --workspace=client` и сервер на 3000). На стенде должно быть
пространство с расходами: создайте его в браузере, в «Настройки → Другие устройства» получите ссылку и передайте
её первому запуску любого скрипта — сессия сохранится в `client/e2e/.state/`:

```bash
node client/e2e/regress.mjs before 'http://localhost:5173/#/device/<token>'
```

## Сценарии

- `regress.mjs <метка>` — 54 прежних снимка (четыре вьюпорта, две темы, шиты, страница модов, десктопный лендинг; имена
  не менялись) и после них новые состояния со сброшенного аккаунта:
  - 393×659, светлая и тёмная: `history-at-0|2500|6000|end` — «История» на прокрутке и в самом конце, где «Ещё N записей
    до …» (конец дожимается, пока высота списка не перестанет расти), `history-select` — выбор долгим касанием,
    `history-swiped` — строка с красной «Удалить», `entry|history|analytics-arrange` — «Настройка экрана»,
    `entry-allblocks` и `analytics-allblocks-0…N` — все новые блоки, аналитика шагами по 500 px, `entry|history|analytics-large` —
    крупный текст, `analytics-blue` — другой акцент;
  - 390×763 и 320×568: прокрутка «Истории», выбор и открытая строка.

  Аккаунт сбрасывается в начале и в конце (`resetAccount`: «Неделя», экраны по умолчанию, обычный текст, исходный цвет, без
  фильтров истории), счётчик карточки «Сохраните ссылку доступа» и подсказка про удержание закреплены в хранилище перед
  каждой загрузкой (`pinLocalState`), на снимках «Расхода» закрыта вся строка заголовка карточки — в ней текущее время.
  Рядом со снимками — `log.json`: ширина документа после «Настроек»
  (`document.documentElement.scrollWidth`), конец «Истории», высота аналитики со всеми блоками. `regress-compare.mjs a b`
  печатает число отличающихся пикселей на снимок и расхождения `log.json`, картинки отличий кладёт в
  `.shots/compare-regress-a-b/`. Два прогона подряд на стенде дают 0 на всех снимках.
- `row-swipe.mjs [метка]` — строка «Истории» открывается свайпом влево и закрывается касанием и протяжкой обратно: каждые
  ~16 мс в течение ~500 мс сдвиг слоя строки (`transform`), есть ли «Удалить» в DOM и видна ли, нет ли дыры без красного,
  плюс четыре снимка строки на фазу в отдельном повторе жеста (снимок WebKit на ~90 мс останавливает кадры страницы)
  → `.shots/row-swipe-<метка>/`. На main «Удалить» есть у всех строк списка и видна всё
  закрытие.
- `cards.mjs [метка] [--inbox=N]` — карточка над «Историей» пропадает и возвращается (`context.setOffline`): каждые ~16 мс
  высота карточек или их обёрток и верх первой строки, плюс снимки в отдельном повторе → `.shots/cards-<метка>/`. `--inbox=N` подменяет ответ
  очереди карт, и сверху стоит ещё «N операций с карты ждут разбора». На main список прыгает на высоту карточки за один кадр.
  `regress-compare.mjs a b row-swipe|cards` ставит сводки двух прогонов рядом.

  Все сценарии берут вход по порту адреса (`.state/webkit-<порт>.json`; у dev-сервера 5173 — прежний `webkit.json`),
  сервис-воркеры выключены, ожидания ограничены 15 с, у каждого скрипта есть общий предохранитель по времени. На стенде:
  `MOAPP_BASE=http://localhost:4431 node client/e2e/regress.mjs before "$(node client/e2e/perf/stand.mjs link --port=4431)"`
  — ссылка нужна первому запуску на каждом свежем стенде: у стенда своя копия базы.
- `swipe.mjs [chromium]` — свайп карточки расхода: тупик, к соседу, обратно, двойной флик; `diff.mjs` считает
  разницу между соседними кадрами (подмена карточки должна давать десятки пикселей, не тысячи).
- `analytics.mjs [chromium]` — смена периода, месяца, недели, категории и валюты покадрово: число, высота карточек,
  индикатор загрузки.
- `landing.mjs` — гостевая стартовая страница и шит создания на 1440×900 и 393×659.

Подводные камни WebKit собраны в памяти проекта: `new Touch()` там недоступен, касания собираются через
`document.createTouch`, а `mask-image` на прокручиваемом контейнере ломает отрисовку на iOS.

## Стенд замеров (`perf/`)

Любая ревизия приложения на своём порту с одним и тем же годом расходов: 1 500 трат за 12 месяцев, 10 тегов,
четыре валюты. Настоящий сервер из снимка `git archive`, продакшен-сборка клиента без минификации, отдельная
SQLite в `.perf-work/` в корне репозитория (вне `client/`, чтобы vitest не находил тесты в снимках кода), без
исходящих запросов. Все стенды получают копию одной базы, поэтому ревизии сравнимы
попиксельно и по кадрам, если снимать их в один день.

```bash
node client/e2e/perf/stand.mjs seed                     # один раз в день: база и вход WebKit/Chromium
node client/e2e/perf/stand.mjs up main --port=4411       # ревизия: ветка, тег, хэш или «.» — рабочая копия
node client/e2e/perf/measure.mjs webkit --port=4411 --label=main
node client/e2e/perf/measure.mjs chromium --port=4411 --label=main --count
node client/e2e/perf/measure.mjs chromium --port=4411 --label=main --throttle=4
node client/e2e/perf/swipe.mjs webkit --port=4411 --label=main
node client/e2e/perf/budgets.mjs main                   # бюджеты из perf/budgets.json, код выхода 1 при провале
node client/e2e/perf/budgets.mjs main perf-branch        # два прогона WebKit рядом
node client/e2e/perf/stand.mjs link --port=4411          # ссылка входа для regress.mjs на этом стенде
node client/e2e/perf/stand.mjs down --port=4411
```

Из отдельного git worktree стенд запускается с `PERF_WORK=<основная копия>/.perf-work`: база и вход
общие, а сборка рабочей копии получает метку по имени каталога и не мешает соседям. У каждого — свой порт.

`measure.mjs` проходит 17 сценариев: первое открытие вкладок, прокрутку «Истории», переключения, цифры на
клавиатуре, сохранение, шит валюты, фильтр и его сброс, свайп ленты вкладок, «неделя → месяц», простой. Пишет
самый долгий кадр, застывание (сумма задержек кадров длиннее 20 мс), коммиты React, число элементов, а в Chromium —
время главного потока. `--count` считает отрисованные компоненты, `--profile` — самые тяжёлые функции,
`--allblocks` включает все новые блоки экранов, `--fixslot` нужен ревизиям до исправления ширины страницы после
«Настроек». Время на Mac с M4 Pro для iPhone 13 умножайте примерно на 1,7; замедление Chromium ×2 близко к iPhone 13,
×4 — к слабому телефону или режиму энергосбережения. У WebKit без экрана нет аппаратного композитинга, поэтому его
цифры прокрутки пессимистичны; пересчёт стилей, раскладка и скрипт переносятся честно.
