# Client API contract

All endpoints are relative to `/api`, use JSON and the shared PIN session cookie. The cookie must be `HttpOnly`, `SameSite=Strict` and `Secure` in production. Dates are ISO 8601 UTC strings. IDs are UUIDs generated by the client, which makes retried/offline creates idempotent.

## Session

- `GET /session` → `{ "authenticated": boolean }`
- `POST /session` with `{ "pin": string }` → `204`, creates the session cookie. Invalid PIN → `401`.
- `DELETE /session` → `204`. The client also removes its trusted-device marker, cached bootstrap and offline outbox.

## Bootstrap

`GET /bootstrap` returns all data needed to start and work offline:

```ts
{
  expenses: Expense[]
  categories: Category[]
  currencies: { code: string; name: string; symbol: string; decimals: number }[]
  rates: { base: 'RSD'; date: string | null; ratesToRsd: Record<string, number> }
}
```

`ratesToRsd` means units of RSD for one major unit of the source currency. It must contain `RSD: 1`. `date` can be `null` during the first background refresh. `currencies` should contain the full searchable ISO 4217 catalogue, with RSD, EUR, USD and RUB at minimum.

## Expenses and idempotent synchronization

```ts
type Expense = {
  id: string
  amountMinor: number       // positive integer
  currency: string          // ISO 4217
  categoryId: string
  note: string | null       // max 200, optional
  occurredAt: string
  createdAt: string
  updatedAt: string
  version: number
  deletedAt: string | null
}
```

All expense writes, online and offline, use `POST /sync` with `{ operations: SyncOperation[] }`. Each operation has a client-generated UUID `operationId`, type `createExpense | updateExpense | deleteExpense`, and payload. The operation is persisted in IndexedDB before the first network attempt. Every retry uses exactly the same operation ID, so a lost response cannot repeat a write.

The response has `{ results: SyncResult[], serverTime: string }`; result status is `applied`, `unchanged`, `conflict`, or `error`. Applied/unchanged operations leave the outbox. Conflicts retain the local operation and current server expense until the user explicitly chooses “discard local and reload server”. Validation errors roll optimistic UI back. HTTP 401 locks the app; HTTP 400/500 also roll optimistic UI back.

## Categories

```ts
type Category = {
  id: string
  name: string
  color: string             // CSS hex color
  placement: 'main' | 'additional'
  sortOrder: number
  archivedAt: string | null
  version: number
}
```

- `POST /categories` with `Category` → created `Category`; the client ID makes this idempotent.
- `PATCH /categories/:id` with editable fields plus `archived: boolean` and current `version` → updated `Category`. Archiving keeps past expenses intact.
- `PUT /categories/order` with `{ "ids": string[] }` → `{ "categories": Category[] }`. The array includes all active category IDs; its order is authoritative within each placement, and returned categories contain their incremented versions.

## Errors and offline replay

Errors use `{ "error": { "code": string, "message": string, "details"?: unknown } }`. Validation returns `400`, missing/expired session `401`, absent resource `404`, stale version `409`.

The client batches queued expense operations oldest-first, up to 200 per `/sync` request. Category mutations are intentionally online-only and roll back with a clear message if unavailable or rejected. Successful bootstrap reads are cached in IndexedDB. The service worker caches the application shell, never API responses.

## Analytics and time zone

Online analytics always comes from `GET /analytics?from=YYYY-MM-DD&to=YYYY-MM-DD&currency=RSD`, using historical rates for the full expense range. Offline, the UI labels an estimate calculated from the last cached rate snapshot. Expense input, history grouping and calendar dates use `Europe/Belgrade`; persisted timestamps remain ISO UTC.

## Trusted-device offline cache

After a successful PIN entry, this browser is treated as a trusted device so cached expenses can be displayed without a network connection. The PIN itself is never stored. Anyone with access to the unlocked browser profile may read cached expenses. Settings therefore exposes “Выйти и удалить локальные данные”, which deletes the session cookie, trusted-device marker, cached bootstrap and outbox. Do not enable offline use on a shared or public device.
