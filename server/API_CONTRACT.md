# Moapp API contract

All JSON endpoints live under `/api`. Except for `GET /api/health` and `POST /api/session`, they require the signed `moapp_session` cookie. The cookie is `HttpOnly`, `SameSite=Strict`, and `Secure` in production. Errors use:

```json
{"error":{"code":"VERSION_CONFLICT","message":"Expense was changed","details":{}}}
```

Amounts are positive integers in the currency's minor units. IDs generated by clients must be UUIDs. Timestamps are ISO 8601 strings. Mutations use integer `version` values for optimistic concurrency.

## Session and bootstrap

- `POST /api/session` `{ "pin": "..." }` — log in. Alias: `POST /api/auth/login`.
- `GET /api/session` — check the current session. Alias: `GET /api/auth/session`.
- `DELETE /api/session` — log out. Alias: `POST /api/auth/logout`.
- `GET /api/bootstrap` — all categories (including archived ones needed to label history), all active expenses, ISO currency metadata, latest rates to RSD, and analytics default. The UI filters category buttons by `archivedAt`. `rates` has `{base:"RSD",date,ratesToRsd}`; before the first successful refresh it contains at least `RSD:1`.
- `GET /api/health` — liveness/database quick check; does not require a session.

Login is limited to five attempts per minute and repeated abuse is temporarily banned. The PIN is checked with `scrypt` and constant-time comparison; only a SHA-256 digest of each random session token is stored in SQLite.

## Expense shape

```json
{
  "id":"uuid", "amountMinor":12500, "currency":"RSD",
  "categoryId":"products", "occurredAt":"2026-08-03T12:30:00.000Z",
  "note":null, "version":1, "createdAt":"...", "updatedAt":"...", "deletedAt":null
}
```

- `GET /api/expenses?from=&to=&categoryId=&currency=&cursor=&limit=50&includeDeleted=false`
- `GET /api/expenses/:id`
- `POST /api/expenses` — complete expense input. Repeating a UUID is idempotent and returns the existing object.
- `PATCH /api/expenses/:id` — changed fields plus required current `version`.
- `DELETE /api/expenses/:id` — JSON `{ "version": 2 }`; soft-deletes the row.

A stale version returns HTTP 409 with `error.code=VERSION_CONFLICT` and the current server object in `error.details.current`.

## Category shape

```json
{
  "id":"products", "name":"Продукты", "color":"#7CB98B",
  "placement":"main", "sortOrder":0, "version":1,
  "createdAt":"...", "updatedAt":"...", "archivedAt":null
}
```

- `GET /api/categories?includeArchived=false`
- `POST /api/categories` — `{id?: uuid,name,placement,sortOrder?,color?}`. Retrying the same UUID with compatible fields returns the existing category with HTTP 200; differing fields return `IDEMPOTENCY_CONFLICT`.
- `PATCH /api/categories/:id` — changed fields plus required `version`; `archived` can restore/archive.
- `DELETE /api/categories/:id` — `{version}`; archives instead of removing history.
- `PUT /api/categories/order` — `{ids}` containing either every active category or every active category in one placement group. Order is applied inside each placement group.

## Offline synchronization

`POST /api/sync` accepts at most 200 operations in one transaction:

```json
{
  "operations":[{
    "operationId":"uuid",
    "type":"createExpense|updateExpense|deleteExpense",
    "payload":{"id":"uuid", "version":1}
  }]
}
```

Each `operationId` is persisted. A retry returns the stored result with `replayed:true` and never repeats the mutation. Result statuses are `applied`, `unchanged`, `conflict`, or `error`. Conflict results include the current expense.

For all expense operation types, every result has `operationId`, `status`, and, when applied, the canonical server `expense`. Create returns version 1, update returns the incremented version, and delete returns the soft-deleted expense with `deletedAt`. The top-level response is `{results,serverTime}`. Because the complete result is stored before the transaction commits, a response lost by the client can be retried with the same `operationId` and recovered deterministically.

## Exchange rates and analytics

Frankfurter v2 data is cached in SQLite with EUR as the pivot currency. The service refreshes on startup and every 24 hours. Historical analytics request the needed date range; on network failure the closest cached rate is used. Expenses remain in their original currency.

- `GET /api/rates/status`
- `POST /api/rates/refresh`
- `GET /api/rates/convert?amount=10&from=EUR&to=RSD&date=2026-08-03`
- `GET /api/analytics?from=YYYY-MM-DD&to=YYYY-MM-DD&currency=RSD`

Analytics returns `totalMinor`, counts, daily points, category totals, weekday totals, and calendar points, all converted to the requested currency. `missingCurrencies` makes partial results explicit when no cached conversion is available, and `rateDate` reports the oldest rate involved.

## Persistence

SQLite uses WAL, foreign keys, a five-second busy timeout, forward-only migrations, soft deletion, and indexed chronological queries. Production expects `DATABASE_PATH=/data/moapp.sqlite`; the `/data` directory must be a persistent Docker volume and is the path Litestream replicates to R2.

`app_meta.backup_heartbeat` is written at application startup and every six hours. Backup monitoring can compare this ISO timestamp with the restored database to verify replica freshness.
